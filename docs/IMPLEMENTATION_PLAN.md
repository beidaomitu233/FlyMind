### D01 基线、供应与样本核验

1. 检查未提交改动并建立清单，不覆盖现有工作；记录应用版本、Node、MCP SDK、数据库路径和当前启动方式。
2. 核验上级 draw.io 31.5.3 资源、来源、LICENSE/NOTICE、目录大小、哈希及完整性；决定复用该固定版本或记录升级理由。不能默认用在线最新协议替代本地验证。
3. 在 FlyMind 的测试数据副本验证现有 SQLite 在线备份、恢复及记录数量。区分 `data/flymind.sqlite` 与上级 `.local-data/pm.db`。
4. 固定一份 PBS 主流程及五类基础样本，来源可追溯，记录节点、边、角色、阶段、分支和回流；保留真实业务，脱敏后形成夹具。优先读取现有存档；缺少原图时记录缺口，不编造业务关系。按 PRD 五维规则记录基准，每个后续任务同步检查生成质量。
5. 确认字体分发许可与 worker 浏览器供应。记录实际目标机器，后续性能结果使用同一基线。

验收：资源能在本机离线加载；当前数据库能从备份恢复；PBS 预期关系经核对；供应记录可复现。交付建议为 `docs/validation/drawio-supply.md` 与脱敏测试夹具，文件真实产生后再加入索引。

2026-10-16 项目经理验收通过：见 [供应与协议核验](validation/drawio-supply.md)、[数据与样本基线](validation/drawio-data-baseline.md) 和 [验收台账](DEVELOPMENT_TRACKER.md)。通过范围是当前机器的可复现基线、原生基础协议、数据库副本恢复与来源关系保留；不是可分发资源包、完整应用恢复或图形质量门槛通过。正式供应授权继续由 V04 跟踪，字体/Chromium 固定供应在 D04 落实，PBS 现存业务问题不得在迁移时自动“修正”。

### D02 PBS 内容编译与原生文档

实现 content → 模板 → 原生文档，不使用 AI 坐标。确立主绑定、子元素及业务/装饰边界，覆盖长标题、判断、阶段、回流和并行。

验收：PBS 原生形状可编辑；连续依赖不挤一排，阶段与内容对应；XML → content 往返等价；普通内容输入的视觉字段被拒绝。浮动文字不撑长主流程。原生二维容器能力不满足时，记录模板调整及显式归属交互，不扩大为自研容器引擎。

2026-10-16 项目经理验收通过：原生表格泳道、严格 v3/Hash/重投影、安全解析及有限文案 patch 已实现；独立全套回归 106/106、构建及三样本真实编辑器往返通过。详见 [引擎报告](validation/drawio-engine.md)、[项目模型报告](validation/drawio-project.md) 和 [验收台账](DEVELOPMENT_TRACKER.md)。首次图片审查发现的表头/边标签/阶段标题问题已退回修复；密集区少量线路交叠及来源业务质量问题继续跟踪，不认定 G1 已通过。

### G1 PBS 贯通门槛

必须按顺序完成：AI 纯内容创建 → 原生编辑节点和线路 → 增删/复制/跨角色编辑 → 保存并重新读取 → AI 增量修改业务 → 检查无关人工布局保留 → 关闭页面后台导出 → 复开数据一致。

至少覆盖两轮人工/AI 交替编辑，并加入一次并发冲突与一次 worker 失败。任何语义失配、已保存数据丢失、旧图冒充新图或严重排版问题均不得通过。通过后才启动 D06/D07 的批量工作。

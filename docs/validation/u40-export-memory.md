补充：图形列表的元信息此前先读取所有完整文档，再逐个解码；现在同步迭代读取，仍逐条执行原有完整校验、保持顺序及 SQLite 错误优先级。工作区快照中的元信息读取也使用相同方法，但快照返回的完整图形数组仍然占用内存。独立 Windows 进程的合成样本（80 条、每条 512 KiB XML；包含建立内存数据库的开销）峰值约 262.0 → 205.2 MiB，耗时 373 → 381 ms，返回元信息 SHA-256 一致；单次样本不是实际服务器或整体服务峰值。同步解析期间读取游标保持打开，可能延长 SQLite 读快照；未减少最终需返回的全部图形数据。

MCP 所用 `/records` 列表原本对整批文档无上限并发做完整原生 XML 校验；现保持同一完整快照、校验和输出顺序，同一请求最多两个并发，并在每条完成后释放源记录引用。测试失败时停止启动后续校验，已经开始的另一条可能继续到结束；多条同时损坏时，所报告的首个错误可能与旧版无上限并发不同。一次独立 Windows 进程合成样本（12 张仅画布图，每张 600 个 cell、XML 约 79 KB，真实校验代码，不含浏览器）峰值约 145.1 → 126.9 MiB，耗时约 1091 → 1112 ms，结果 SHA-256 一致；仅为单次组件测量，仍会先在 SQLite 中读取全部图形快照，不代表并发请求整体内存，也不保证所有规模的延迟。

读取完整图形快照本身也已逐条从 SQLite 解码，避免先保留整批原始数据库行，再构造整批文档；返回的完整文档仍必须保留。同一隔离环境中 80 条、每条 512 KiB 合成 XML 的完整记录读取单次峰值约 288.7 → 221.8 MiB，结果摘要一致，耗时约 426 → 392 ms；包含内存数据库自身开销，不可将此降幅直接用于估算生产。游标会在同步解码期间保持，可能延长读快照。

回收站列表使用相同的逐行读取策略，保留删除时间排序、旧格式字段及 SQL 错误优先级。80 条各 512 KiB 合成文档的单次进程峰值约 256.1 → 190.4 MiB，输出摘要一致；这是包含合成 SQLite 数据库的 Windows 组件测试，不代表线上存储内容或整服务内存。

导出快照的持久化 SHA-256 对普通 JSON 逐段写入相同的规范内容，不再先构造完整规范 JSON；特殊对象、代理、访问器、自定义数组、过深或超保守估计上限时退回旧实现。差分覆盖边界代理项、控制字符、无效值、异常顺序、species 和 1000 组混合 JSON；导出、历史重试与仅画布集成 19/19 通过。独立 Windows 进程的一次合成样本（XML 3,686,400 UTF-8 字节，限额内，但不是有效图）峰值约 92.2 → 70.9 MiB，耗时 21.7 → 14.6 ms，摘要相同。不保证超限回退输入节省内存，也不保证遭篡改的全局 JavaScript 内建方法与原行为一致；该样本不是浏览器或服务全流程的测量。

未接入产品的 PNG data URI 分块原型见 `scripts/probes/svg-data-uri-chunks.mjs`。固定 vendor 表达式及 Unicode/代理项/padding 差分 4/4；22 MiB 合成输入在独立 Windows Node 进程中峰值约 218.4 → 197.1 MiB，输出摘要一致。仅为各一次合成编码测量，不能证明 Chromium 实际内存或图片像素等价；需限定作用于导出且通过浏览器/CSP/离线/像素及中断清理验收后才可考虑接入。另对只在 XML 元数据检查中暂时缩短固定字体 CSS 的原型做过 16 MiB 合成输入比较，约 99.2 → 98.8 MiB，收益不显著且解析器容错存在安全边界，已撤销该原型，不作用于应用。

SVG 绘图完整性签名改为逐节点写入哈希，不再同时构造整棵中间对象树和 JSON 字符串；异常深度、超量估算或部分 JavaScript 原型异常时退回原算法。仓库五类示例、随机树、空 defs、字体错误顺序和深层回退与旧签名差分，及字体和资源安全回归合计 16/16 通过。20,000 组节点的合成 SVG 两个独立 Windows 进程签名一致，单次峰值约 192.5 → 161.5 MiB，耗时约 422 → 418 ms；另一组先前测量耗时增加约 9%，不能据此保证性能。该测量不含 Chromium，仍需要完整真实绘图验证。

最终 SVG 的资源检查原本已经在固定字体封装子进程中完整解析过 XML；现在利用同一 DOM 顺带核对原有尺寸规则，固定子进程、渲染结果对象及完全相同 SVG 字符串共同建立进程内证明，制品写入使用该已验证的字符串。未获证明、被改写、代理/访问器、尺寸字段过长或超出原有 96 MiB JSON 输入预算时，仍运行原来的独立校验；已取消信号和非法超时仍先走原错误处理。此路径减少一次 SVG 跨进程复制及第二个子进程，避免其额外的队列/内存准入，因此部分旧流程报忙或内存不足的任务可能成功，属于明确行为变化。合成完整字体约 21.9 MB 的隔离流水线单次对照：子进程数 2→1，父进程峰值约 218.5→176.0 MiB，耗时约 1023→636 ms，SVG 摘要一致；仅是父进程峰值，不包含子进程或 Chromium 的同时 RSS。伪造凭据、对象/字符串修改、取消、超时、XML 尺寸和固定子进程传递等定向回归 43/43；仍需真实 Linux 绘图链路验收。

## 源码确认的放大点

1. 字体源16,437,364B，每张SVG即使只有几个字也附完整OTF base64，约21.9MB。SVG字符串经独立资源DOM扫描、IPC、父进程Buffer转换及写后整文件复读，出现多份同时存活。正常流程不存在逐节点各嵌一份字体，但仍有固定的每图大负担。
2. `prepareNativeArtifacts`同时建立PNG/SVG/drawio/JSON/project五个Buffer，再逐文件`readFile`复读；写后校验应继续保留，但可使用分块写与流式摘要替代全量复读。
3. `delivery`只返回文件路径，却经`file()`把五份制品完整载入Buffer，重复SVG的大字节分配；可保留发布身份/路径/mtime/SHA全部检查，仅流式核对。
4. 导出snapshot主要为业务内容与XML，不含最终SVG字体字符串；24节点参考XML约85KB。SQLite队列持久snapshot与当前worker单任务不是21.9MB字体字符串常驻缓存。不能因此否认浏览器或多进程的实际驻留，renderer生命周期由另一固定代理测量。
5. MCP PNG需协议base64，最终8MiB预算已经存在。对已知超额的资源不再下载原件；长度未知或不可信时通过有界流读取，超额即取消，保留已有文件、路径和错误合同。
6. 工作区备份盘点最多并发16次整文件读取，随后备份复制、固定供应指纹和数据库摘要也使用整文件读取；大制品、浏览器或数据库可造成多份大 Buffer。正在改为有界流式检查与复制，不能以删除旧导出或降低备份完整性替代。
7. 多人协作原先每个 peer 持有完整图形记录及额外 workspace/principal 引用；增量比较只需要修订号与 XML。候选只保留这两项，仅在 team、图形、数据根、修订和 XML 内容全部相同时复用，不引入独立全局缓存。每个 peer 保留独立鉴权和当次完整事件；断开释放引用。多人、权限撤销、历史修订、不同数据根和慢客户端等联测12/12通过；尚无服务整体 RSS 对照。为避免共享异步读取造成时效与故障扩散，未合并各用户的数据读取。

备份候选已改为最多四路、每路64 KiB盘点，失败时等待已启动读取结束；复制、制品验证、供应/SQLite摘要及恢复组件改为流式。64 MiB同文件单次样本：原整读约179 MiB峰值、57.4 ms；流式盘点约121 MiB、62.0 ms。专项5/5通过；Windows沙箱创建链接受限，授权临时目录复验通过。部分失败目标会留在未发布暂存位置；不能声称全备份峰值已全面受限。

数据库逻辑状态摘要现逐表读取、排序并增量哈希，保持原清单的 canonical JSON、重复行和 JS UTF-16 排序格式。八张表、每表256行的隔离内存数据库最终单次同工况进程对照中，原实现峰值393.5 MiB、293.5 ms，候选192.8 MiB、244.1 ms，最终摘要一致；无强制GC。完整备份、恢复、回滚4/4通过；独立审查发现特殊的 SQL 失败与非JSON行编码失败的先后次序差异，已修正并以五项定向差分覆盖，包括晚到SQL错误、WITHOUT ROWID、磁盘只读连接与数值边界。逐行迭代会让单表读取语句保持更长时间；单张表排序仍需保留该表行文本，其他历史校验也可能全表加载，不能将这个样本当作所有数据库的峰值上限。极大数据库旧实现可能因构造完整 JSON 超出 V8 字符串上限，候选有可能成功处理，该错误边界有意改变。

备份校验读取导出任务时，改为同步逐行解析，不再同时保留整组原始 SQLite 行与完整解析结果；仍返回完整 jobs，保留行序和 SQL 失败相对 JSON 解析失败的优先级。同一 80 条、总计约40 MiB 的隔离样本中，旧方法单进程峰值约239 MiB、39.0 ms，候选约213 MiB、41.2 ms；摘要一致。差分4/4与完整备份/恢复4/4独立通过。结果仍随完整 jobs 和最大单行增长，且逐行 JSON 解析会延长读语句占用时间，不能视为总体内存上限。

图形和历史修订仍采用原 SQL、原 `.all()` 和验证顺序；每行完成前只清除该行在数组中的额外引用，已处理行可在后续阶段被 GC。串联图形80 MiB、修订20 MiB和任务10 MiB的单次隔离合成样本，旧方法峰值约207 MiB，候选约173 MiB，摘要一致；GC 时机不受保证。失败顺序专项2/2、完整备份恢复4/4通过。这不避免最初 `.all()` 的峰值，也不代表生产工作区结果。

## 最小候选方案与边界

- 复用固定、带SHA和metrics验证的WOFF2分片，按实际SVG文字选择覆盖分片并离线内嵌。未知字符、复杂variation或供应不完整时回退原OTF，不删字，不引入网络字体依赖。
- 字体变化不修改文字、位置、图元、配色或非字体CSS，继续核对原生绘图安全签名。保留字体来源及OFL；不能只移除字体降低内存而牺牲离线可用性。
- 制品逐份生成、分块写、流式读回SHA；delivery只做相同完整性核对，不为路径响应载入全部制品。
- 不擅自关闭SVG、取消五制品交付或改18工具schema。可选format按需生成需要单独确认导出快照和重试合同，本片先保持功能完整。

## 测量与验收

使用隔离绘图器生成的小图和24节点技术架构图的原生SVG，依次封装小图、架构图、小图、架构图，不强制GC。`output/u40-memory/svg-comparison.json` 中记录：线上旧52b的字体封装子进程峰值约278.7 MiB，本批候选约100.1 MiB；这只是本机Windows单个子进程的样本，不是生产服务总体峰值。小图SVG从21,922,693降至675,196字节，架构图从22,004,938降至1,826,218字节。当前增加的复杂文本安全回退可能使特定图形仍使用完整字体。

`output/u40-memory/offline-raster.json` 对比旧版和候选导出的离线图像，小图、架构图及中英文/生僻字样本像素一致，没有外部字体请求；此结果仅覆盖这些样本，不能代表全部语言和所有CSS场景。字体子集缺失、复杂脚本、CSS派生文字等不确定情况回退完整OTF；继续校验字体供应哈希和导出资源安全性。

字体相关定向测试11项、制品导出13项通过；MCP有界读取及原协议定向测试22项通过。隔离测试必须使用工作区内临时目录，默认沙箱临时目录曾出现重命名权限错误。新增测试已接入云候选流水线；本批尚未发布，线上旧版不具备这些优化。

嵌入字体资源的 SHA 对规范 base64 改为 64 KiB 分块解码；非规范、base64url、空白等输入回退原 Buffer 解码，保留宽松解码语义和安全校验。同一 21.9 MB 编码文本一次隔离对照：旧实现约116.7 MiB、21.8 ms；候选约95.7 MiB、43.0 ms，摘要一致。与数据库摘要和 SVG 安全联测 16/16 通过；这是单项测试，不能推算浏览器进程或整机峰值。

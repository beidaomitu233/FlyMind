# FlyMind 绘图内容标准 1.0

目标：图中能快速读出核心结构、先后和结果，修改准确作用于原图。此标准约束业务内容，坐标、尺寸、形状、字体和连线走线由渲染器负责。机器检查只能保证可检查的基础项，不能代替业务正确性核对。

## 每次绘图的步骤

1. 先明确“这张图回答什么问题”，选择一种图形。只画当前目标，不能把整份 PRD 原文搬进来。
2. 从材料提取主体、动作、条件和交付物。保留关键判断、失败出口和回流，不凭空补充规则；信息缺失时只询问会改变业务关系的问题。
3. 一个节点只表达一个动作、问题、模块或概念。名称使用“动作＋对象”“是否＋条件”或简短名词。不要加“步骤一、执行此操作、相关说明”等无信息文字。
4. 写完整真实关系，再调用 validate_diagram。修复质量报告中的 error，检查 warning；最后创建并检查图片，交付 PNG、源文件和编辑链接。
5. 解释、取舍和待确认问题主要写在对话回复里。不得为了显得完整而新增注释、重复标题、说明卡片或无业务意义的节点。

## 五类图形

| 类型 | 节点表达 | 必须核对 | 不应出现 |
|---|---|---|---|
| 流程图 | 起点/终点、动作、判断 | 每个动作接入真实流程；判断出口有互不重复的条件；每个分支有后续或结果；返工指回真实步骤 | 孤立步骤、用长文本描述几步操作、以注释代替条件和连线 |
| 泳道图 | 角色负责的动作，阶段归属 | 角色交接有边；先后与并行准确；汇合等待全部必需前置；失败和交付闭环 | 按角色堆字而没有依赖；为了对齐更改角色/阶段；把跨角色交接误当并行 |
| 架构图 | 同一抽象层级的模块、职责和核心能力 | 分层理由一致；职责边界清楚；只画有必要解释的依赖/接口；条目是能力名称 | 把操作步骤混成模块；重复堆砌功能；用模块框盛放整段方案说明 |
| 思维导图 | 根问题、同级分类、下级概念 | 单一中心；兄弟分支遵循同一种分类维度；下级确属上级；建议不超过 5 层 | 机械拆词、同级重复主题、把线性执行过程伪装成主题树 |
| 数据流架构图 | 来源、处理/汇聚、去向、必要的数据契约 | 数据从哪里来、经过什么、到哪里去；读写方向、回写/反馈正确；卡片正文只留必要信息 | 只有漂亮卡片没有关系；把产品说明书塞进 description；丢失数据去向 |

## 简洁程度与机器检查

| 内容 | 建议 | 新增或加重时拒绝保存的上限 |
|---|---|---|
| 普通节点标题 | 中文/中英混排 18 字以内；纯外文 64 字符以内 | 32 字 / 110 字符；标题超过 3 行或有 3 个及以上句号/分号的段落 |
| 开始、结束标题 | 12 字 / 36 字符以内 | 24 字 / 72 字符 |
| 数据卡片正文 | 120 字符以内 | 240 字符 |
| 其他业务备注 | 180 字符以内 | 500 字符 |
| 架构模块条目 | 8 项以内，短语命名 | 12 项；单项中文 32 字 / 纯外文 100 字符 |
| 连线文字 | 只写条件或数据名称 | 中文/中英混排 24 字 / 纯外文 80 字符 |

字符数包含空格和标点。不能通过删除必要业务、藏到大段备注、附加说明节点来绕过限制；需要时按真实职责拆分、分图或向用户说明范围。`note` 是用户确实需要的浮动批注，不是步骤，不计入流程骨架；说明占比过高会提示检查。

机器检查还会拒绝不匹配的业务节点类型、孤立节点、不连通的流程片段、判断缺少两个出口、判断条件缺失/重复、结束节点继续向后连线。架构图不要求给所有模块强行加箭头。业务是否完整、条件是否真实、抽象层级是否合理仍由 AI 核对。

报告含 `passed/score/issues`，通过要求无 error，基础分至少 80。分数只反映这些机器检查项，不能等同于专业评审。每个 issue 给出定位、原因和修改方向。历史图允许逐步修复原有问题；MCP 修改不得新增或加重不合格项，网页手动编辑仍可保存草稿。

## 修改原图的标准

1. 必须先 get_diagram 读取最新 revision 和内容，识别用户要变更的步骤、判断、角色、关系或措辞。
2. 修改前列出需要增删的业务节点和边；删除/替换步骤时同步接好前后节点，修改判断时同步更新条件出口。
3. 保留未涉及的业务、ID、人工归属与渲染。优先 patch_diagram，不能重建一张相似图来覆盖原图。冲突后重新读取并合并。
4. 修改流程时，真正修改步骤和关系，不能只加“说明：应该如何处理”的 note。修改文字时，直接改原节点或边的文案。批注只在用户明确要求时添加。
5. 工具顶层 editIntent 可选 structure（默认）、wording、annotation。annotation 只用于用户明确要求批注；普通流程修改即使声明 wording，也不能只添加说明来交差。该字段不是 content 的字段。
6. 修改后对照用户要求核对差异，再检查所有出口、回流、结束和交付物，返回更新后的图形。

## 读取入口

- get_drawing_guide 始终返回本标准与技术规则，指定 kind 同时返回该类型模板。
- MCP 资源 flymind://drawing-standard；网页接口 /studio-api/drawing-standard。
- 仓库 docs/DRAWING_STANDARD.md 与 skills/draw-with-flymind/SKILL.md。

标准文档供 AI 理解，core/drawing-quality.ts 执行内容检查；两者不能把排版参数写进内容层。

# ADR 002 固定远程MCP入口与服务端更新

日期：2026-10-20。状态：设计基线已形成，待实施/真实部署验收。来源：用户要求客户配置尽量不更新、后续由云端升级。

## 决定

1. 推广主入口使用固定HTTPS `/mcp` 和OAuth，沿用协作分支现有路由。首次配置后保持正式域名、路径及授权resource稳定；FlyMind应用契约版本独立记录，不以更换所有客户URL做日常升级。
2. 内容规则、自动布局、模板及引擎部署在云端。稳定MCP接入进程与经常更新的绘图应用进程分开，避免布局修复也终止客户端连接。
3. 工具名/既有输入输出保持兼容；说明、样例与校验器同包发布，guide取服务端当前规则。工具清单变更发通知，同时保留旧缓存调用兼容。
4. 原工作台UI、draw.io及内容/渲染分层保留。云端网页/MCP共享云端图形；旧本地图形保留，上传/迁移由用户显式选择。
5. 网关会话升级、账号授权与绘图服务发布分别处理。承诺正常更新免改配置/免重装绘图包，不保证任意第三方客户端永不重连或登录。
6. 按用户最新决定纳入v1.1，与团队管理、团队空间、操作记录、导入及完整同图实时协作一起交付。远程接入切片可先验证，但不能以此代替v1.1完整验收。先完成可部署交付，真实公网发布按实际服务器和正式域名验证。

## 依据与影响

当前客户使用本地STDIO，代码和依赖驻留用户机器；换Markdown、npm latest或服务端Git提交都不能自动替换已运行进程。远程MCP将执行权移到服务端，更新成本由维护者承担。

代价是云端存储与运维、账号鉴权、目标平台出图供应，以及服务故障时无法保证离线绘图。必须保留本地版的独立定位，不能混称“数据完全在本地、引擎全部免本地升级”。当前协作分支有可复用的远程/OAuth基础，但授权批准UI、真实控制面联调及发布隔离尚未完成。

完整发布清单、幂等与任务保护、SQLite单活、回滚、兼容验收及U01–U07顺序以[MCP持久更新方案](../MCP_UPDATE_STRATEGY.md)为唯一详细依据。本ADR不宣布已上线，不修改当前用户连接或数据。

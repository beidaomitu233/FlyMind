# 发布中断与回执恢复

本说明对应源码中的受控发布器；只有完成独立验证并通过授权安装后才适用于实际环境。不要将源码变更当作已安装或已部署。

应用和控制面各自在其 root 保护的 `stateDirectory` 使用发布锁；锁目录权限为 `0700`，新建的回执和恢复标记为 `0600`。`recovery-required.json` 表示服务回滚、子进程或其外部操作的结果需要控制台人工核查。新回执写入期间分别使用 `.application-receipt-pending.json` 或 `.control-plane-result-pending.json`，这些标记在回执数据和目录同步完成前阻止重放与解锁。发布器也拒绝旧版按 release 建立的 `*.receipt-pending.json`，以及历史 attempt 下的 `.result-pending.json`。标记或锁状态无法读取时必须按不确定处理。

**不要仅删除标记、锁、候选目录或临时文件来恢复发布。** 在隔离维护窗口由受权管理员核对锁 owner、该次受控进程和可能的后代、systemd 作业及服务实际状态、current 与 gateway 引用、回执和运行版本摘要；控制面还需核查 Flyway、JAR、数据库备份及迁移兼容性。先保全回执、候选、stage、日志和备份，必要时从经过验证的独立备份恢复。确定不存在仍在运行的旧操作、确认数据与回滚方案后，再按经审定的控制台恢复程序处理；本说明不授权自动清锁或自动恢复数据库。

回执和目录同步失败时，磁盘可能出现不完整回执或带 `ok:true` 的表面结果；只要 pending 存在，不能将它当作成功重放的证据。最终删除 pending 后的目录同步失败也必须保留本次锁；在该阶段回执本身已先完成同步，重启后仍应核查实际状态。

# 应用版本只读清点与保留审查

本模块只读，不删除、不改名、不写回执、不释放锁，也不读取图形数据库或备份。当前没有历史版本自动回收器；`manual-review-only` 是人工复核提示，不是删除许可。用户正在处理服务器，禁止据此访问或修改生产。

本地隔离夹具示例（Linux；目录必须明确传入且为真实绝对路径）：

```sh
node deploy/cloud/release-inventory.mjs --root /tmp/flymind-fixture/releases
```

入口在 Linux 读取本进程的挂载表；挂载表不可用时停止清点。仅统计指定目录下的版本树，不跟随链接、不遍历子挂载和不同设备；遇到异常目录、文件类型、权限或时间/条目预算问题报告不完整。默认最多 150,000 条、30 秒，单次系统调用可能超出时间预算。只输出版本 ID、计数、逻辑长度、文件系统报告的分配块和错误类别，不输出文件名或文件内容。分配块可因硬链接或写时复制共享，**不能作为可释放空间**，也不保证与 `du` 的去重口径一致；其他进程在清点期间修改目录时，结果不是原子快照。

CLI 默认没有可靠的引用证明，所有结果为 `hold`；不默认使用任何生产路径。程序接口 `planReleaseRetention(inventory, evidence)` 可接收上层提供的完整性标记及引用，分别覆盖 current、网关、回滚版本、compact 当前基线、活动进程、在途发布/不明故障和所有团队待完成及可重试导出所需的供应。任一缺失、引用找不到或供应无法对应时，全局保持 `hold`。这些输入仍属调用方声明，候选的 manifest 也只是元数据读取，不是全树 SHA 验证，因此计划始终返回 `evidenceVerified:false` 和 `deleteAuthorized:false`。仅可用于指出下一步应调查的范围。

现有应用发布回执没有可靠记录原 `oldTarget`，不能按时间或最近成功版本猜上一个回滚版本；导出任务分散在各团队 SQLite，快照、WAL 和可重试失败任务须一并考虑。应用与网关工作目录、在途 compact 重放及不同发布锁都必须由未来的受信执行器重新核实；错误或不确定的锁/回滚状态一律保留。任何将来的执行方案还需独立设计全树验证、锁/进程竞争防护、数据根及备份隔离、可恢复操作、审计和磁盘不足处理，不能直接消费此报告执行删除。

定向测试：`node tests/cloud-release-inventory.test.mjs`；测试使用隔离临时目录和模拟挂载表，覆盖链接、硬链接、未识别项、预算、缺失/矛盾证据及只读保护。Windows 沙箱可能拒绝测试夹具创建链接；Linux 挂载表、真实权限及生产状态仍须单独验证。

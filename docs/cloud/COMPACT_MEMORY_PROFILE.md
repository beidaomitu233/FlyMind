# 可选的 compact-1g 内存配置

默认配置不变：浏览器与 SVG 工作进程准入要求至少 512 MiB，SVG 子进程 V8 堆上限 256 MiB、RSS 上限 384 MiB，浏览器运行中可用内存低于 128 MiB 时取消。只有服务环境变量明确设置 `FLYMIND_MEMORY_PROFILE=compact-1g` 才启用紧凑配置：浏览器与 SVG 准入 384 MiB，SVG 子进程 V8 堆上限 160 MiB、RSS 上限 256 MiB；浏览器运行中可用内存低于 64 MiB 时取消。未知值使用默认配置。compile 等非 SVG 工作的原有 384 MiB 准入、256 MiB RSS 和 256 MiB 堆上限不变；重活子进程运行中仍保留 128 MiB 保护，既有队列、取消、关闭与浏览器 sandbox 不变。

浏览器运行压力余量的调整是预算适配，不会降低实际内存占用，也不是操作系统内存限额；必须由管理员配合已验证覆盖服务及所有后代的 `flymind.slice` 1 GiB 硬边界和不重叠的发布维护流程使用。配套 `MemoryHigh=1000M` 与浏览器 64 MiB 余量对应的 960 MiB 之间名义上仅余 40 MiB；内核和应用的采样及内存口径不同，且突发分配可能越过阈值，因此不保证应用取消先于内核节流或 OOM。安装配置或启动进程本身不能证明该边界有效，也不能保证任意图形在此配置下成功。堆/RSS 较小可能令复杂 SVG 工作失败；余量较低可能增加 cgroup OOM 风险。配置前后应在等价的受限环境验证真实浏览器 sandbox、字体、PNG/SVG 与编辑保存，并记录 cgroup 峰值及 OOM 事件；失败应保持明确错误和原任务重试语义，不改用其他渲染路径冒充成功。

紧凑配置还对满足保守条件的原生图使用已校验的 WOFF2 字体分片，供原编辑器页面与原生 PNG 导出共同使用；字符集取原 XML 及已解码内容的超集，始终包含完整 core，所选文件合计超过 2 MiB 时回退完整 OTF。仅接受已审的基础形状、静态简单 HTML 和固定无文本技术图标；公式、动态占位、复杂文字或样式、未知图形和图片等回退完整 OTF。常规配置继续使用完整 OTF。所选分片不会保证每张图都能在 1 GiB 中完成；Linux 平台候选须通过六类标准样本的原生 PNG 完整 OTF 与选片逐像素对照。

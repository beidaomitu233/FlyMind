## 1. 简介与交付边界

将线上协同一期、[MCP持久更新](../MCP_UPDATE_STRATEGY.md)、批量导入及本轮图形质量优化合成一个可部署版本：用户管理团队，在团队空间共享并同时编辑同一张图，追溯操作；AI通过固定HTTPS MCP修改同一份图形。我们发布云端服务，客户日常不再更新本机绘图包或配置路径。

保持原FlyMind侧栏、图形行、新建/导出与draw.io画布体验，保留内容与渲染分层。沿用此前完整账号/本地授权目标，账号与团队复用Java控制面，不另写一套密码系统。已有本地图形不自动上传或合并。

本批先交付可部署版本及部署自动化；正式域名和服务器待用户提供后实际核验上线。不等待SSH停止本地代码/契约准备，也不将缺环境的测试写成已通过。

## 2. 角色与空间

- 平台管理员：开通/停用账号、必要的团队管理和审计支持；不默认向普通成员暴露管理端。
- 团队所有者/管理员：管理团队及成员；保留最后所有者保护、邀请有效期、角色上限与退出规则。
- 编辑者：团队内新建、导入、编辑、分组、删除/恢复及AI写入；无团队成员管理权。
- 查看者：读取、查看操作记录与导出；不允许借导入、直接API、协同消息或MCP写入。

团队空间和应用内文件夹不是同一层级：切换团队后列表、文件夹、回收站、操作记录、协同连接和MCP授权均属于所选空间。不同团队可以有相同diagramId，不能跨空间检索/下载。

## 3. 核心术语

| 术语 | 含义 |
|---|---|
| 团队空间 | 由服务端授权的图形数据边界，不是用户提交的磁盘路径 |
| 文件夹 | 空间内的列表分组；图形在文件夹里时不重复显示在根列表 |
| 操作记录 | 已实际提交操作的可追溯事实，不是每个临时鼠标动作 |
| 协同修订/ACK | 服务器确认落库的顺序与回执，收到后才表示已保存 |
| 导入批次 | 一次选择/拖入的文件集合，允许重试但不重复建图 |
| 发布制品 | 与源码提交及摘要绑定的不可变服务包/镜像，不用latest代替版本 |

## 4. 业务主链路

1. 登录 → 个人/团队空间 → 文件夹或根列表 → 新建/导入/打开图形。
2. 同图两位成员编辑 → 服务端校验身份和基线 → 合并/明确冲突 → 持久保存 → ACK并增量同步 → 操作记录可查。
3. MCP首次授权同一空间 → 读取当前规则与图形 → 带revision/requestId修改 → 在线画布收到变更 → 真实PNG及受保护编辑/下载链接。
4. 选择文件/目录或拖入 → 自动识别合法结构 → 按导出身份聚合 → 确定目标 → 导入一次 → 进入目标列表/文件夹 → 可编辑/导出/继续由AI修改。
5. GitHub构建验证 → 同一不可变制品到测试环境 → 发布到生产 → 排空/切换/健康检查 → 成功记录或恢复原版本；客户MCP地址保持不变。

## 6. 权限与隔离要求

网页、MCP、导入、协同连接、历史与下载使用同一权威身份和权限事实。成员被移除、账号/团队停用后，不只阻止新网页请求，也必须阻止后续协同提交与MCP调用。云端浏览器草稿按userId+teamId+workspaceIdentity+diagramId隔离；切空间前保存或明确保留草稿，不能恢复到另一主体。

## 7. 数据需求

- 控制面持久保存账号、成员关系、邀请、授权/刷新/撤销事实。复用冻结协作分支的Java接口和受控后台副本，源管理系统只读。
- 空间保存业务content、渲染XML、图形修订、文件夹、回收站、导入来源和幂等回执。首期SQLite单活写入，持久卷与代码/镜像分离。
- 协同房间有已提交顺序及恢复基线；不能仅以内存广播代替落库。未ACK编辑、重启和跨版本接管均可明确恢复。
- 操作记录以服务端身份和提交结果产生；图形变更及其事件在同一工作区事务/可靠outbox中一致，不接受客户端自报操作者冒充事实。团队管理事件在Java权威事务中记录；不假定MySQL与SQLite可跨库原子提交。
- 导入只写新顶层身份与当前空间归属，不能从源文件继承团队权限、旧回执或历史。来源文件及摘要留存，不改用户原文件。
- 发布清单记录源码SHA、制品digest、规则/适配器/引擎供应与数据迁移级别。旧queued/retry任务可按原供应继续，缺供应明确报错。

## 9. 详细功能与边界

### 9.1 多人实时编辑

保留完整目标。不同成员修改不同元素保留双方有效结果；同字段/删改/重连冲突按已定义策略明确提示，保留本地未确认内容，不能后写静默覆盖。远端修改通过增量patch应用，保留视口、选区和本地未确认编辑，不循环重载整张XML。Undo只撤销本人相应操作，不能撤回对方后续编辑。

人工与AI经过同一修订协调入口。保存成功但ACK丢失后，以原requestId重放原回执，不重复事件或图形；重连先取缺失修订再重基。页面级背景/样式等属性必须实际同步或明确拒绝，不能只有节点坐标同步。

### 9.2 导入与操作记录

详见[导入与记录契约](V1_1_IMPORT_AND_ACTIVITY.md)。默认行为固定如下：

- 文件拖到文件夹即以该文件夹为目标；拖到根列表即未分组；显式导入可选择目标。不得同时出现在根列表和文件夹。
- 可递归扫描拖入目录，但本期不因此新增完整嵌套目录产品；按用户选定目标归档，可在预检中选择新建同名目标文件夹，不静默创建多层目录。
- 自动检查实际JSON/XML结构及引用，不仅检查扩展名。人工合法草稿可以保留并报告内容问题，不把AI质量准入强加于导入，也不自动改节点/连线凑合格。
- 同一批 `png/svg/content.json/project.json/drawio` 若能确认是同一图，只产生一条可编辑记录；同内容的完整project JSON优先以保留人工渲染，其次纯content JSON。原生源文件作为另一种可识别输入；PNG/SVG附件不反推节点，不单独变成重复图。
- 同名不等于同图；同源ID但内容不同、两个JSON互相冲突时明确列出选择，不按扩展名优先静默丢弃。没有可恢复节点源的纯图片单独提示未导入。
- 每图导入原子化，成功/重复跳过/格式失败/冲突分别有结果；批次重试只处理原失败/未确认项，不回滚或重复已成功图。文件夹创建也需幂等、失败不遗留空占位。

### 9.3 MCP与线上升级

完整机制沿用[MCP持久更新方案](../MCP_UPDATE_STRATEGY.md)：固定 `/mcp`、OAuth、工具兼容和规则同包。远程结果移除服务器绝对路径，返回真实PNG、受保护HTTPS链接及资源。仅更新guide文档不能代替校验器/渲染代码升级。

### 9.4 GitHub自动部署

采用[GitHub部署方案](../deployment/GITHUB_DEPLOYMENT.md)。PR只验证；主分支构建通过后进入测试环境；生产由发布Release或选择同一已验制品触发，避免线上临时编译不同内容。后续正常发布无需维护者反复SSH操作，更不需要每位客户更新配置。

部署密钥使用GitHub环境Secrets和服务器受限部署身份；服务器应用密钥不打进镜像/公开产物。已保存图形、账号、协同日志和制品放持久目录。GitHub流水线串行控制加服务器部署锁共同防止并发切换，失败有可判断的回滚边界。

## 10. 交互要求

- 延续极简侧栏：团队切换进入账号/空间入口；文件夹保持折叠树与组内显示，不新增统计卡片和大段说明。
- 导入复用现有入口/拖放区域；过程显示必要进度和结果，只在冲突/失败时展开详情。不要为低频动作增加常驻按钮。
- 操作记录在图形更多菜单进入侧栏，按时间分页；按需筛选，不堆新仪表盘。协同在线成员与保存状态应清楚，不能以成功toast掩盖未ACK编辑。
- 云端维护更新用稳定状态条说明、保留画布和草稿；禁止黑屏、闪烁、重置滚动位置或强制刷新未保存页面。

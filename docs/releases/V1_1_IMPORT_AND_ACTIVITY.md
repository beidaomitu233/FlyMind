# v1.1 导入与图形操作记录方案

日期：2026-10-20。状态：方案经PM定点复核并冻结，功能仍待实施验收；不是现有功能说明。本任务只新增本文，不修改应用、分支或版本。

v1.1包含账号/团队管理、团队空间、多人实时同图编辑、固定远程MCP及持久更新、导入优化与图形操作记录。用户已明确包含实时编辑；不能将CAS冲突提示或一次保存替代多人实时协作。本文只定义导入与操作记录同其他能力的边界，不新增协同协议实现。

## 2. 简洁入口与目标规则

沿用原工作台，不另做导入管理页。

- 工作区菜单保留一个“导入…”；打开文件选择时可选多个文件，旁边提供“选择文件夹”。文件夹行菜单“导入到此文件夹…”预选该组。
- 文件拖入侧栏文件夹：该文件夹为目标；拖到列表背景：默认“未分组”。高亮实际目标，不遮盖画布，不把文件拖入误当画布图元拖动。
- 目录可递归扫描，但**所有选中图形默认进入用户选定/投放的同一个目标**，不按来源子目录静默新建多层组。预检可显式选“新建〈来源目录名〉文件夹”，只新建一个同级目标；来源子路径仅用于定位和来源记录。
- 文件夹目标优先于来源目录名。多目录混选不能擅自选某个目录名：默认既有目标，用户需要时自行命名新组。文件夹名冲突列出已有候选，不按名称偷偷并入另一个组；服务端使用组ID。
- 一次预检弹层：目标选择、总览“可导入/已存在/冲突/不支持”、紧凑文件行。每行展示相对路径、识别类型/名称、选中的规范源、问题与预期动作。默认仅勾选明确可导入项；“确认导入N张”一次提交，取消零业务写入。
- 导入成功只刷新列表并展开目标；单图可打开，多图保留原活动图，结果行提供“打开”。不因后台批量完成强行切换用户正在编辑的图。需要打开新图时仍走原保存/草稿离开保护。

一期不做嵌套目录管理、自动跨团队导入、服务器绝对路径输入或自动上传用户整盘。目录读取只来自用户明确选择/拖入；默认跳过隐藏文件、链接/快捷方式和非支持文件，不读取.env/凭据或跟随远程引用。浏览器无法保证检测的特殊文件必须在预检明确拒绝，不靠扩展名假定安全。

## 3. 规范源、导出集合与去重

### 3.1 先看内容，再选来源

后缀/文件名只帮助识别，不能证明结构或同源；每份候选均由服务端验证。

1. 完整v3 project正式投影验证，保留人工几何、样式及装饰；完整v2 project走受控无损迁移，阻断项不得退回纯content重编译。
2. 有完整业务绑定的drawio经真实投影，可保留原生画布。无业务元数据只能按已支持canvas-only能力保原稿；损坏FlyMind业务元数据必须报错，不静默降级。
3. 纯content JSON只带业务内容，需新编译。若与同集合完整project的规范业务内容一致，**默认只选完整project**，content作为同源附件，不再建第二张。
4. PNG/SVG通常是预览制品。同批有对应的已验证JSON/project/drawio规范源时，只导入规范源一次，PNG/SVG不另建图。纯图片没有可验证的完整编辑源时提示“仅图片，无法还原节点”，不OCR猜节点、类型和关系，也不生成虚构空业务图。
5. 如后续启用图片内嵌drawio源提取，须单独验证完整元数据、解压预算与投影；不能仅见SVG XML或PNG扩展块就视作可编辑源。此项不是当前已实现能力，也不是基础批次导入的前置。

完整源优先仅适用于业务一致且来源可核实的集合；两份完整源的人工渲染明显不同或版本关系不明时，列为冲突，由用户选择，不能用“优先级”悄悄丢掉新人工布局。

### 3.2 去重证据与冲突

- 强证据优先：经摘要验证的导出manifest/源关联；其次原始文件SHA256和正式解析后的来源文档ID、规范内容摘要、原生渲染签名等一致性证据。没有manifest的旧导出也必须可处理，不能强迫补造清单。
- 同名/同目录、标题相同、文件mtime相近仅是候选分组线索，不能单独合并两个JSON。PNG/SVG即使同名也不宣称已验证为该JSON的预览；它们不具备独立可导入源时显示为未导入的伴随图片即可。
- 比较content时不因project envelope/时间字段不同制造重复；业务ID/节点ID/关系必须按定义参与比较。不同来源图ID即使看起来相似，也不全局按去掉ID的文本hash合并。
- 同批相同字节重复只留一份；完整project与同业务纯content只建一张。相同来源ID但业务内容不同，或同业务内容但两个完整源的几何/装饰不同，必须提示冲突，默认不覆盖、不任选。
- 已登记来源再次导入同一团队空间，默认“已存在，跳过/打开已有图”，即使新的requestId也不能重复建图。索引由服务器维护，不仅靠浏览器缓存。并发两个成员导入相同来源时，事务唯一约束收敛到同一张已授权图。
- 同一已识别图改选目标文件夹，不隐含创建副本或移动已有图；显示已有归属，用户可明确另行移动。确需重复图时点“另存副本”，产生新requestId/新顶层ID，并记录显式override，不覆盖原图。
- 原图已在回收站：显示“已删除”，不偷偷恢复或重建原ID；用户可走独立授权恢复，或明确另存新ID。永久删除/tombstone按现有规则处理，去重记录不能让文件下载或旧ID复活。

去重限于当前授权的团队/工作区，不跨团队查询“是否存在”或泄露别人的标题/摘要。来源摘要一致本身不是授权凭据。

## 4. 预检、预算与提交原子性

建议批次限额在实现前与引擎/网关统一冻结：最多200个扫描条目、50张拟导入图；可编辑原始源合计20MB，展开XML合计64MB。现有每文件/每请求/每XML限制保留。大SVG字体制品可能远超单源预算：有JSON规范源时不必上传配套图片，只在预检说明忽略；不能因此让有效JSON导入失败。图片若尝试独立提取源，则另行检查外层文件与解压额度，不绕过现有上限。

批次按以下两阶段执行，不把全部文件base64塞进一个4MB请求：

1. 建立有期限的上传/预检会话，逐源上传到隔离staging；校验文件名/相对路径，不接受绝对路径、盘符、`..`、NUL或符号链接越界。文件夹仅为逻辑组，来源路径不能直接成为服务器目录。
2. 服务端严格校验schema、合法kind枚举/字段类型、ID唯一、引用/角色/阶段/分层/父子、边端点、无环主题、v3双层一致性，以及XML安全/展开预算。每kind内容表达、长字、历史条件缺口等质量问题单独报告，不混成结构损坏。压缩/多页/外部实体或不支持格式明确拒绝，不猜测修复。使用内容标准1.1报告质量，但**人工导入可保留结构合法的历史质量问题**，不冒充AI新建合格。
3. 服务端产生有期限的预检摘要，绑定actor/team/dataRoot、目标组ID或待建组名、文件hash、规范源选择、去重决定、解析器/适配器版本。客户端不能传“已校验=true”绕过检查；变化须重新预检。
4. 预检后用户确认有效选择，不在后台偷偷忽略错误/冲突源。采用**每图原子、批次可部分完成**：每项使用批次内稳定itemId与分项receipt，分别返回成功、重复跳过、失败或未确认。新目标组在第一条成功导入图的同一事务中幂等创建；零成功不留空组，全部重复跳过也不创建无用目标。不能为批次新增必须全批完成的大型数据库事务。
5. 编译/迁移/来源文件验证在事务外完成；提交前重新向权威控制面确认写权限；短事务中核对该次可信actor/team上下文、workspace identity、组存在、去重唯一键和该itemId的分项receipt，原子登记本项图/历史/来源/归属/操作记录；首项成功需要的新目标组一并登记。不能仅凭较早的预检权限提交。跨Java/SQLite的授权竞态须沿统一可信入口收口，不能宣称跨数据库一个ACID事务；已被撤权的新提交不得凭旧浏览器role继续执行。
6. 原文件先不可变发布并核摘要，数据库登记后才可读取；DB失败可留不可见孤儿供有界回收，不能删并发已成功批次的来源。分项receipt与该图业务同事务；batchId关联各项结果而非要求全批数据库原子。网络超时先按原batchId查询，沿用原itemId、requestId及原payload仅重试失败/未确认项；同键改源/目标拒绝，改选择须重新预检。已成功项返回原结果，不回滚、不重复建图或写历史/日志。

长批次期间权限/工作区/目标改变、磁盘不足或某项校验失败，该项不留半记录，受影响的后续项暂停/失败；批次明确显示部分完成，不冒称全部成功。已成功项保留且不重复，失败/未确认项可在重新授权并核对原payload后重试。提交前取消不写业务；执行中取消仅停止尚未提交项，不撤销已成功图。staging过期/取消仅清本批未登记的暂存内容，配额与清理不触碰正式图或其他用户上传。

## 5. 权限与实时编辑边界

- owner/admin/editor可导入、新建组、移动图；viewer仅预览其可读内容和查看记录/导出，不可通过导入、新requestId或目录拖放写入。MCP还须有flymind:write；只有read不得导入/复制/覆盖。
- 团队/用户/actor来自Java的可信授权上下文，非请求体自报。团队切换不能继续提交旧团队预检或receipt，草稿/上传会话按user+team+root隔离。
- 一期默认导入为新图，不提供“同名覆盖当前图”。导入不同版本、恢复历史或替换现图若后续提供，必须独立确认、最新revision CAS，并走统一协同提交；不能以导入路径跳过在线成员编辑。
- 每图事务提交完成后再广播该项已提交的列表/图形事件，无需等待整批结束。实时协同房间只能读取已登记快照；不能先广播临时XML，再因导入失败撤回成功状态。
- 本期包含真正多人实时编辑：导入后的图可进入同一协同房间。具体同步/重基/本地Undo协议由v1.1协同实施方案决定，本文没有实现或验证该能力。

## 6. 图形操作记录

### 6.1 入口与显示

- 原标题“更多”菜单放“操作记录”，默认当前图；侧栏工作区菜单放“工作区记录”，用于导入、分组/移入移出、删除/恢复等事件。按需右抽屉或弹层，不常驻第三列。
- 默认最近记录，显示操作者、人工/MCP/系统渠道、动作、时间、修订及一句数量摘要；按图形、操作者、渠道/动作筛选。展开才看获准的节点ID/字段摘要和对应历史，不默认展示原始JSON/XML。
- 每页50条，用服务端cursor（提交序号+eventId）稳定倒序翻页；不以浏览器时间或仅timestamp排序，不用offset造成新事件插入后重复/漏页。顶部提示“有新记录”，不打断用户正在看旧页。
- 当前团队授权成员可读普通图形记录；离开/移除/团队停用立即拒绝后续读取。平台账号/团队管理属于Java控制面管理日志，不能伪称与图形SQLite同一事务；一期无需把两套日志硬合成一个全局序号。

### 6.2 服务端最小字段

| 字段 | 含义/约束 |
|---|---|
| eventId、commitSequence、eventVersion | 服务端分配稳定事件与工作区提交顺序；客户端不得自报 |
| teamId、dataRootId | 所属授权空间及epoch；对外不泄露目录路径 |
| diagramId、action、occurredAt | 图形及实际动作，服务端提交时间；组操作可无diagramId，另带groupId |
| actorUserId、actorDisplayName、channel | 可信用户ID与提交时显示名；channel=web/mcp/system；多人共同编辑不能全记作“系统” |
| clientId、correlationId | MCP公共client标识/请求关联；不记录Bearer、refresh、cookie、密码或gateway key；内部grant/session可仅存服务端受控审计字段 |
| requestIdDigest、batchId、itemId、sourceSummary | 幂等关联、batchId/itemId及源格式/摘要/数量；不公开本机绝对源路径 |
| fromRevision、toRevision、operationSummary | 真实已持久修订范围、新增/修改/删除节点边数、变更字段与受控ID；不把渲染变化伪装成业务结构变化 |
| sourceRevision、sourceExportId | 仅在已有或另获授权的历史恢复、复制或MCP指定快照导出入口记录实际来源；没有则省略，不猜值 |

对已存在或另获授权的入口记录实际动作：人工/MCP新建、导入/另存副本、内容修改、原生画布修改、自动排版/方向、标题/分组归属、删除/恢复/永久删除、导出任务创建/成功/失败。历史恢复等入口若已存在或另获授权，才记录实际来源与新修订；**操作记录不新增历史恢复功能前置**，不改写旧历史。

### 6.3 原子性、噪声、保留

- 成功的图形/工作区变化与其操作事件同一SQLite事务登记；协同事件只在服务确认实际持久提交后产生。失败不写成功事件；有必要的权限/请求失败写单独受控安全日志，不混入图形修订。
- 不记录每个pointermove、选中、hover、光标或未提交输入。不把原生autosave请求等同真实修订：内容/渲染signature无变化、重复receipt重放均不新增修订或操作事件。一个已提交修订可聚合该次协同提交的多个操作，并保留各真实操作者及关联ID；不能只记最后发送快照的人。协同actor摘要必须以**提交前服务器已持久修订→本次接受并提交的变更**为基准；合并时保留的远端既有变更不重复归因给本次发送者，不能拿过时客户端base与最终整张图的差异冒充其贡献。
- 高频连续编辑在UI可按同用户/会话/图形短时间分组展示，但底层已提交事件不可丢失或把两个人合并成同一actor。共同事务若含多actor，记录actor列表及每actor摘要，不能伪造单一操作者。
- 导出不改变文档revision/updatedAt；其运行状态事件关联jobId和原snapshot revision，不能把失败旧图记作最新成功导出。后台任务事件actor沿原发起者，系统执行者另列。
- **默认不自动清理正式操作摘要**，不设置未经授权的180天删除期限。保留期限与清理属于需显式确定的运维策略，不作为v1.1操作记录UI的前置；未来启用须说明范围并获得授权。图形历史版本、来源原文件、导出制品与安全日志各自生命周期，不能因摘要清理连带删除正式图。
- 永久删除后只留最小审计身份/动作/数量与tombstone关联，移除可还原业务正文和敏感标题；记录入口不能绕过purge恢复原稿。若法规/客户另有留存要求，须明确策略而不是默默保留整份XML。
- 应用层追加写，不提供普通成员改写/删除记录接口；有权限的服务器运维仍可能修改底层存储，不把普通数据库日志宣传为不可篡改的合规存证。

## 7. 实施与验收切分（均待实施）
